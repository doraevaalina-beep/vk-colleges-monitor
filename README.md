# VK → единая лента для ChatGPT

Готовая схема для мониторинга списка сообществ VK без прямого чтения `vk.com` со стороны ChatGPT.

## Что делает

Раз в час GitHub Actions:
1. читает `sources.txt`;
2. получает последние записи через официальный метод VK API `wall.get`;
3. при первом запуске запоминает текущие записи как базовую точку и **не выдаёт старые посты как новые**;
4. на следующих запусках добавляет только новые записи;
5. публикует:
   - `docs/feed.json` — удобная структурированная лента;
   - `docs/feed.xml` — RSS;
   - `docs/health.json` — какие группы читаются, а какие вернули ошибку;
6. хранит VK-токен только в GitHub Secrets. В публичную ленту он не попадает.

VK API version: `5.199`.

## Что уже внутри

В `sources.txt` внесён весь список VK-сообществ из задачи.

## Что нужно сделать один раз

### 1. Получить сервисный ключ VK

Нужен **сервисный ключ доступа собственного приложения VK**. Для публичных стен этого достаточно.

Общий путь:
- создать приложение VK для разработчиков;
- открыть настройки приложения;
- скопировать сервисный ключ доступа.

Не вставляйте токен в `sources.txt`, код, сообщения, публичный репозиторий или URL.

### 2. Создать GitHub-репозиторий

Создайте новый репозиторий, например `vk-colleges-monitor`.

Загрузите в корень всё содержимое этой папки, сохранив структуру:
- `.github/workflows/update-feed.yml`
- `docs/...`
- `monitor.py`
- `sources.txt`
- `state.json`
- `requirements.txt`

Репозиторий может быть публичным. Секрет в него не попадёт.

### 3. Добавить секрет

GitHub:
`Settings → Secrets and variables → Actions → New repository secret`

Имя:
`VK_SERVICE_TOKEN`

Значение:
ваш сервисный ключ VK.

### 4. Разрешить workflow записывать состояние

GitHub:
`Settings → Actions → General → Workflow permissions`

Выберите:
`Read and write permissions`

### 5. Включить GitHub Pages

GitHub:
`Settings → Pages`

Source:
`Deploy from a branch`

Branch:
`main`

Folder:
`/docs`

После публикации будут URL примерно такого вида:

- `https://USERNAME.github.io/REPOSITORY/feed.json`
- `https://USERNAME.github.io/REPOSITORY/feed.xml`
- `https://USERNAME.github.io/REPOSITORY/health.json`

### 6. Запустить первый раз вручную

Откройте:
`Actions → Update VK feed → Run workflow`

Первый запуск только создаёт базовую точку. Текущие старые посты не отправляются в ленту как новые.

После этого workflow запускается каждый час на 15-й минуте (UTC).

## Как проверить, что всё работает

Откройте `health.json`.

Там:
- `ok` — сообщества, которые VK API прочитал;
- `errors` — закрытые, удалённые, переименованные или недоступные источники;
- `new_posts` — сколько новых записей найдено на текущем запуске.

Это особенно полезно для большого списка: после первого запуска сразу видно, какие ссылки реально требуют отдельной обработки.

## Что дать ChatGPT

Только публичную ссылку:

`https://USERNAME.github.io/REPOSITORY/feed.json`

VK-токен ChatGPT не нужен и передавать его сюда не надо.

После этого можно настроить задачу:
- проверять `feed.json` раз в час;
- брать только записи, которых ещё не было;
- присылать оригинал;
- делать рерайт без воды, канцелярита и ИИ-штампов;
- сохранять все имена, даты, цифры и факты;
- добавлять прямую ссылку на оригинальный пост VK.

## Что с закрытыми группами

Сервисный ключ подходит для открытых публичных стен. Если `health.json` покажет `Access denied` для закрытого сообщества, оно потребует отдельной авторизованной схемы доступа.

Не стоит пытаться передавать логин/пароль от VK в этот скрипт.

## Ограничения

- Проверка идёт раз в час, поэтому это не realtime.
- За один запрос к каждой стене берутся последние 20 постов. Для колледжей этого с большим запасом достаточно на час.
- Текст, написанный **только внутри картинки**, VK API не превращает в текст. Ссылка на фото сохраняется в `attachments`, но OCR здесь специально не выполняется.
- GitHub Actions запускается по расписанию не с гарантией до секунды и иногда может задержаться.
- Если VK изменит API или правила токенов, интеграцию нужно будет обновить.

## Безопасность

- Никогда не коммитьте сервисный ключ в Git.
- Храните его только в `VK_SERVICE_TOKEN` (GitHub Secrets).
- Если ключ случайно оказался публичным — отзовите его в VK и создайте новый.
